## 作品简介（298 字）

石窟壁画盐害由湿度超阈的累积时长触发。现有洞窟微环境研究均以均方误差为训练目标，导致模型平均意义上精确、风险意义上失效——实测MSE下窟内RH的点R²达0.59，超阈召回率仅0.047、漏报95%以上。本项目重构为风险对齐预报：以延迟嵌入Koopman输运算子（闭式解、可微、可解释）把室外气象轨迹映射为窟内湿度风险，用阈值加权评分规则twCRPS替代MSE。超阈F1由0.072→0.164、AUC由0.862→0.903，点精度不降反升；24h预警检出率35.1%、平均提前46.3h。窟内无公开实测已显式声明：窟内序列为文献参数化物理模型的合成标签，并以跨窟留一验证5/6通过检验外部效度。

## 一、作品概述

### 1.1 背景介绍

石窟寺壁画与彩塑的主要病害之一是**盐害**（酥碱、疱疹、起甲），成因链是：洞窟内相对湿度超过某一阈值 → 可溶盐吸湿潮解 → 干燥时再结晶膨胀 → 壁画地仗层结构破坏。敦煌研究院的业务口径以 **62%** 为警戒线；文献进一步把**潮解起始**定在 67%（Demas 2015）、把**吸湿突变**定在 75%（npj Heritage Science 2025）。也就是说，保护决策关心的从来不是"平均湿度是多少"，而是"**未来 24–72 小时会不会超过阈值、超过多久**"。

现状与缺口：

- **外场监测已到位**：甘肃省气象部门在莫高窟窟区核心区布设了 **7 套区域自动气象站**（气压、气温、湿度、降水、风向风速）。
- **窟内监测也已到位**：敦煌研究院已监测 **115 个莫高窟洞窟**，甘肃省石窟寺监测预警平台接入院属 **6 处石窟**。
- **但现有平台是"实时 + 事后"**：提供实时监测、越限报警与事后处置。
- **缺的正是"提前"那一环**：从"已经超了"提前到"还有 48 小时要超"，把被动处置变成可排班的预防性干预——选时开闭窟门、调节通风、调整游客批次。洞窟损伤**不可逆**，这段窗口是唯一的干预机会。
- **数据侧的客观困难**：窟内微气候长序列实测数据**实质不存在公开数据集**（详见附录 1 与 `docs/02_数据集方案.md`）；窟外则有 NASA POWER 逐小时再分析资料（2001–2025，219,144 小时，缺测 0）可用。

本作品补的正是这一环：**只用室外公开气象数据，预报窟内未来 24–72 小时的超阈风险**。

### 1.2 目标定位

**要解决的具体问题**：在窟内实测标签不可得、决策不可逆的条件下，建立一个**可训练、可解释、可在普通 CPU 上运行**的窟内湿度风险预报算法。

**技术指标**（下表全部为测试段 2021–2025 的实测值，不是训练集表现）：

| 指标 | 设定的目标 | 实际结果 |
|---|---|---|
| 24 h 超阈风险排序能力 | AUC > 0.80 | **0.860**（输运算子）/ **0.876**（GBDT 读出） |
| 最危险档位（75%）排序能力 | 显著优于基线 | AUC **0.759 → 0.879** |
| 平均预警提前量 | > 24 h | **46.3 h** |
| 48 / 72 h 时效不塌陷 | 不低于同时效 oracle | F1 **0.101 / 0.060**，均高于 oracle 的 0.064 / 0.043 |
| 全流程算力门槛 | 纯 CPU 可运行 | ✅ 无梯度下降、无 BPTT、无 GPU |
| 外部可复核性 | 至少一条不含合成标签的独立验证 | ✅ ICCP **12 个真实岩溶洞穴**（真实观测） |

**对照基线**：初稿方案的查表式一阶传递函数 `RH_in = a·RH_out(t−Δ) + b`（`a`、`Δ` 为文献摘抄常数）在同一测试段上有**两种实现，结论必须分开说**：
**递归实现**（极点 a = 1.000920 > 1）必然饱和，AUC 0.4995、F1 0.000，**从不预警**；
而**静态传递形式**（可部署化后）AUC 0.824、F1 0.076、预警检出率 29.8%，
其**原文无自回归形式**的 AUC 更达 **0.896**——排序能力甚至高于本作品，
真正的问题是**绝对量级被压缩**（校准阈值落在 48.9%，召回率仅 0.0375）。
本作品据此把结论定为「**初稿抓到了形状、丢掉了量级**」，而非「与随机无异」。

**预期效益**：把"事后处置"变为"提前 46.3 小时排班"。对开放洞窟而言，一次可预判的高湿过程意味着可以提前决定调整游客批次或临时闭窟，而这正是不可逆损伤发生前唯一的干预窗口。**本作品不声称已产生现场经济效益**——量化的现场收益需与文保单位联合试点后评估，这一边界已在 §6.2 显式声明。
## 二、需求分析

### 2.1 业务痛点：风险是"超阈时长"，不是"平均误差"

敦煌研究院的官方业务口径明确：**空气相对湿度一旦超过 62%，就可能加速壁画地仗层中的
盐分潮解**；配套的 CO₂ 预警阈值为 1500 ppm（樊锦诗 2013；郭青林 2026；汪万福公开表述）。
学术侧的阈值分三级（见 §2.3 表与 §3.1）。这三个阈值共同刻画的是同一件事：

> **损伤 ∝ 超阈的持续时间与反复次数**，而不是湿度的平均值。

这意味着一个预报系统哪怕平均误差很小，只要它**从不当湿度接近阈值**，在业务上就等于零。
本项目的第一项实验就是这一论断的直接实证（§3.1）。

### 2.2 能力缺口：文献自己把问题留在了桌上

*Heritage Science* 2022（DOI 10.1186/s40494-022-00805-3）用 XGBoost 预测室内相对湿度超限，
原文明确写道：

> "A desirable improvement of the model would be **predictions for periods longer than 24 h
> ahead**, still maintaining a high test accuracy."

并抱怨 "difficulties in obtaining good historical climate data sets"。**">24 h 多步预测"与
"数据稀缺"这两条未解问题，正是本项目直接接住的问题。**

### 2.3 需求的形式化：三个子问题

| # | 子问题 | 为什么是算法问题 |
|---|---|---|
| P1 | **目标变量不可观测** | 窟内湿度无公开实测，无法直接监督；只能通过物理代理间接定义 |
| P2 | **目标函数与决策错配** | 损伤 ∝ 超阈时长，而现有工作一律优化 RMSE/R² |
| P3 | **多步预报误差在极值处最大** | 24–72 h 推进的误差累积恰在最危险的尾部最严重 |

**三级业务阈值（逐级独立出处，构成本项目的风险判据）**

| 阈值 | 含义 | 出处 |
|---|---|---|
| **62%** | 业务预警线 | 中国气象局《中国气象报》援引敦煌研究院业务口径：RH 超过 62% 时盐溶解、遇干燥空气结晶膨胀而加剧酥碱（配套 CO₂ 1500 ppm） |
| **67%** | 可溶盐潮解起始 | Demas et al. 2015, DOI 10.1007/978-3-319-09000-9 |
| **75%** | 吸湿与渗透性突变 | npj Heritage Science 2025, DOI 10.1038/s40494-025-01756-1 |

### 2.4 需求侧政策依据

**外场气象观测能力已经就位**。中国气象局《中国气象报》报道：「经过精心选址、周密部署，
在与敦煌研究院莫高窟开放管理委员会反复沟通后，甘肃省气象部门在莫高窟窟区核心区安装了
**7 套区域自动站**，实时提供气压、气温、湿度、降水量、风向风速等数据」，并与敦煌研究院
保护所**共享 24 小时气象信息**[12]。

**行业协同机制正在形成**。2025 年 6 月，受中国气象局、国家文物局指导，由**甘肃省气象局
牵头**，山西省气象局、河南省气象局共同发起建立的**文物保护气象服务联盟**在敦煌成立[13]。

**省级监测平台已经上线**。甘肃省石窟寺监测预警平台已统一接入敦煌研究院院属 **6 处石窟**
（莫高窟、麦积山、炳灵寺、榆林窟、西千佛洞、北石窟寺），敦煌研究院石窟监测中心对莫高窟

石窟寺监测预警平台」列为重点建设项目[15]。

→ 结论：**外场观测网与窟内传感器网都已就位，缺的是把外场数据提前转化为窟内风险

**提前 24–72 小时**的那一环——让预警从「已经超了」变成「快要超了」。

**（4）在作品中的具体作用**：气象数据是三层链路**唯一的输入**。

- **L1 多步外场预报**：提供未来 s 时刻的外场状态；
- **L2 输运算子**：把室外轨迹延迟嵌入为高维可观测量 `Ψ(u)`，再读出为窟内代理 `ĥ_t = wᵀ·Ψ(u_t)`；

需要说明的是，本作品**没有自行采集数据**（与文保单位无合作关系，见 §6.2），因此走的是"公开数据 + 文献参数化物理代理"的路线，并用三条外部效度链路（跨窟留一 / 同窟同期实测 / ICCP 真实洞穴）来约束这条路线。

### 3.3 L2：延迟嵌入输运算子（可微物理代理）

**为什么需要算子层**：窟内无实测标签，只有物理模型生成的合成标签。若把逐时步推进的
物理模型直接接在预报网络后，会有两个问题——**难以高效反传**、**推理代价高**。
因此需要一个闭式解、可微、可解释的高速代理。

**理论依据**：Takens 嵌入定理与 HAVOK（Brunton et al., *Chaos as an intermittently forced
linear system*, Nat Commun 8, 2017, DOI 10.1038/s41467-017-00030-8）——在受迫系统中，
未被观测的标量可观测量可从被观测量的延迟坐标中重构。

**算子形式**：设外场驱动 :math:`x_t \in \mathbb{R}^d`，构造提升特征 :math:`\Psi(u_t)`：

- **演化**：:math:`\Psi(u_{t+1}) \approx K \Psi(u_t)`
- **读出**：:math:`\hat h_t = w^\top \Psi(u_t)`

:math:`K, w` 均由**岭回归闭式解**给出，**不含反向传播**。:math:`K` 的特征值谱给出
物理可解释的时间常数与衰减率。

**特征设计（每族对应明确物理量）**

| 特征族 | 维度 | 物理含义 |
|---|---|---|
| 快变延迟坐标 | 48 × 5 = 240 | 日循环与天气过程的高频响应 |
| 多尺度滑动均值 | 12 | 窟壁温度本质是室外气温的低通滤波结果。窗口 1/3/7/30/90/365 天 |
| Magnus 比值项 | 6 | 因 :math:`RH = q/q_{sat}(T)`，把温湿耦合非线性直接写进特征 |

共 **258 维**，**严格因果**（第 t 行只依赖 :math:`\le t` 时刻信息）。

### 3.4 L3：风险对齐训练

**方法**：Gneiting & Ranjan (2011, DOI 10.1198/jbes.2010.08110) 的阈值加权连续排序概率评分

```
twCRPS(F, y; v) = ∫ [ F(z) − 1{z ≥ y} ]² · v(z) dz      （积分遍历全体实数 z）
```

实现上采用等价的**加权分位数（pinball）损失**：
:math:`\mathcal{L} = \sum_k \omega_k \rho_{\tau_k}(y - q_k)`。

**本作品的改动**：让权函数成为**由输运算子导出的状态相关变量**

```
ω_k(t, h) = 1 + γ · σ( (ĥ_cave(t+h) − r) / s ) · (2·τ_k − 1)_+ · exp( −h / H_eff )
                 (   风险门控   )            (  上尾强调  )      (  时效衰减  )
```

⚠️ **本改动未通过预登记判据**，已降级处理，详见 §3.3。该失败**主动呈现**，不掩盖。

### 3.5 系统的工程约束：纯 CPU 可运行

算子层为闭式解（岭回归 / SVD），**全流程可在普通 CPU 上运行、无需 GPU、无 BPTT**。
这使系统可直接部署在景区边缘设备或研究机构的普通工作站上，符合文保行业算力现实。

## 四、项目实施

### 4.1 总体方案

**一句话思路**：把"预测窟内温湿度"从文保应用问题**重构成算法问题**——在目标不可观测、标签稀缺、决策不可逆的条件下，训练一个**可微的物理代理**，并让训练目标函数与**"阈值 + 持续时间"型损伤判据**对齐。

```
室外公开气象（NASA POWER 逐小时）
        │
        ▼
L1  多步外场预报  ──────────── 提供未来 s 时刻的外场状态
        │
        ▼
L2  延迟嵌入 Koopman / EDMD 输运算子      ← 创新点 2（模型级）
    258 维严格因果特征   Ψ(u_{t+1}) ≈ K·Ψ(u_t)
    闭式解读出           ĥ_t = wᵀ·Ψ(u_t)
        │
        ▼
L3  阈值加权评分规则 twCRPS               ← 创新点 1（模型级）
    三级阈值 62% / 67% / 75%
        │
        ▼
    分级预警 + 预警提前量
```

**架构要点**

- **轨迹式读出**：预报 s 时刻就用 s 时刻的外场特征，因此**读出与时效解耦**，无需逐步滚动。逐步滚动 `K^h` 已被实验否决（`diag_rollout.csv`：h=24 rollout +0.31 vs 直接读出 +0.55，全时效劣于直接读出，见附录 5）。
- **双轨读出**：非线性梯度提升面向业务预报精度，线性算子面向物理解释与可微梯度链路（见 §5.5）。
- **功能结构**：`code/` 是算法包（数据 → 物理代理 → 算子 → 损失 → 实验 → 看板），`tools/` 是交付物生产链（Markdown→PDF、PPT、视频、内容与版式校验）。
- **可视化原型**：Flask + **本地内联 ECharts** 的四页面看板（总览 / 对比 / 验证 / 回放），**前端只展示、不算数**——所有数值均来自 `code/results/` 落盘文件，可审计、可断网运行。

3. **发现并淘汰退化指标**：原始的"超阈持续时长 MAE"对全部时间窗取平均，

4. **诚实标注不可部署基线**：oracle 持续性需窟内实测输入，显式标注、不用于垫底比较。

按赛题要求标注**核心创新层级**（数据级 / 特征级 / 模型级 / 系统级 / 应用级）：

**关键技术**：延迟嵌入（Takens 定理 / HAVOK）与 EDMD 的闭式解结合；`scipy.linalg.expm` 对切换门态的 LTI 子系统做精确离散化；阈值加权 CRPS 的数值积分与内生权重推导。

**关键设计取舍**：见附录 5——三个被预登记判据否决的设计（`K^h` 逐步滚动、twCRPS 内生权重、点预报直接判超阈）原样保留，不删不改。

**人工智能工具的运用方式**：本作品**未使用第三方大模型或智能体作为算法组件**。AI 部分全部为自行实现与训练的机器学习算法（Koopman/EDMD 输运算子、岭回归与分位数回归、梯度提升读出、阈值加权评分规则）。大语言模型仅用于**工程辅助**（文档整理、代码审阅），不参与任何数值结果的产生。

### 5.2 目标函数错配的实证（本项目立论基础）

在标准 MSE 训练下：窟内 RH 的**点 R² = 0.585**（看起来不错），
但**超阈事件的检出严重不足**——测试段（2021–2025）24 h 时效、62% 阈值下
召回率仅 **0.047**，漏报 95% 以上的超阈事件。
（更正：早期材料「从不预报超阈、预报最大值仅 52.8%」的说法在重标定 +
PSC 驱动的公平协议重跑后不再成立，实测 MSE 的 pred_max 为 82.5%——
问题是"偶尔够到、却漏掉绝大多数事件"，业务上同样等于预警失效。）

| 训练目标 | pred_rate | pred_max | F1@62% | AUC@62% | 点 R² |
|---|---|---|---|---|---|
| A：MSE（现有全部工作） | 0.0034 | 83.1% | 0.072 | 0.862 | 0.585 |
| B：MSE + twCRPS（本作品） | 0.0150 | 74.3% | **0.164** | 0.903 | **0.655** |
| C：twCRPS + 内生权重 | 0.0025 | 70.3% | 0.096 | **0.903** | 0.651 |

**B vs A 是实打实的增益**：F1 **0.072 → 0.164**，AUC **0.862 → 0.903**，
召回率 **0.047 → 0.186**，且逐点 R² **不降反升**（0.585 → 0.655）——风险对齐**没有牺牲**点精度。
该增益（F1）在验证/测试两段 × 24/48/72 h 六个格子上全部成立；
AUC 在 62% 口径下同样六格全部为正增益（三档平均口径下为 5 胜 1 负，验证段 48 h 由 0.880 微降至 0.874）
（`code/results/exp03_abc_ablation.csv` 与 `_val.csv`，逐格数字见 `code/results/exp03_full_log.txt`）。

### 5.3 与基线的对比（24 h 时效，62% 阈值，测试段 2021–2025）

| 模型 | AUC | F1 | 预警检出率 | 平均提前量 | 可部署 |
|---|---|---|---|---|---|
| [oracle] Persistence | 0.836 | 0.092 | — | — | ❌ 需窟内实测 |
| **Operator（本作品）** | **0.860** | **0.128** | **35.1%** | **46.3 h** | ✅ |
| FirstOrderTransfer·静态传递（初稿可部署化） | 0.824 | 0.076 | 29.8% | 42.5 h | ✅ |
| RidgeDirect（无延迟嵌入） | 0.739 | 0.053 | — | — | ✅ |
| Climatology | 0.734 | 0.002 | — | — | ✅ |
| FirstOrderTransfer·**递归实现**（初稿原样） | 0.500 | 0.000 | 0.0% | 从不预警 | ✅ |
| FirstOrderTransfer·**原文无自回归形式** | **0.896** | 0.052 | — | — | ✅ |

**要点**：

1. 算子在 **48 h / 72 h 时效上 F1 仍高于 oracle 持续性**（0.101 / 0.060 vs 0.064 / 0.043）——
   长效时效是文保预警的真正战场，初稿的静态传递在 48 h 已掉到 R² 0.093、72 h 为 **−0.011**。
2. **初稿方案的失效机制被实证厘清**，且**必须分两种实现陈述**：
   其**递归推演**（极点 a = 1.000920 > 1）必然饱和，AUC 0.4995、预警检出率 0、
   72 步后 R² = −8.95（数值发散），是"完全无预警能力"；
   但其**原文的无自回归形式** AUC 高达 **0.896**、**排序能力甚至强于本作品**，
   短板在于**绝对量级被压缩**——校准阈值落在 48.9%、召回率 0.0375、F1 仅 0.052。
   本作品因此把结论写成「**初稿抓到了形状、丢掉了量级**」，
   并把它列为对自身最不利的一条对照证据（见 §5.9 与附录 5）。

### 5.4 消融：完整特征配置确有贡献

**方法学要点**：不同消融的特征维度不同，共用正则系数时"某消融反超"可能只是正则强度错配
的伪象。因此**每个配置在验证段独立选择岭回归系数 β**。

| 配置 | β* | 点 R² | AUC | F1 | 命中窗口率 |
|---|---|---|---|---|---|
| [oracle] Persistence（不可部署） | — | 0.428 | 0.836 | 0.092 | 0.330 |
| **Operator-Full（本作品）** | 1e-4 | **0.611** | **0.860** | **0.128** | 0.309 |
| Ablation-无 Magnus 项 | 1e-6 | 0.611 | 0.858 | 0.125 | 0.309 |
| Ablation-短延迟(12 h) | 1e-6 | 0.606 | 0.859 | 0.126 | 0.309 |
| Ablation-无慢变项 | 1e-6 | 0.523 | 0.804 | 0.098 | 0.468 |
| Ablation-仅快变延迟 | 1e-6 | 0.514 | 0.796 | 0.081 | 0.319 |
| RidgeDirect | — | 0.317 | 0.739 | 0.053 | 0.234 |
| Climatology | — | 0.402 | 0.734 | 0.002 | 0.053 |

**结论**：完整特征配置在**点精度、排序能力、事件 F1 三个维度上同时最优**；
各消融均不优于它——"多尺度慢变项 + Magnus 耦合项"的**物理动机特征设计确有贡献**。

⚠️ **需要连带说明的一点**：`Ablation-无慢变项` 的"命中窗口率"（0.468）反而高于完整配置（0.309）。
该指标衡量的是"是否在事件窗口内至少报出一次"，对**报警密度**敏感——无慢变项配置的 F1 只有 0.098、
AUC 只有 0.804，其较高的命中窗口率来自更频繁的报警。因此本作品**不单独引用命中窗口率**，
凡出现该指标处均与 F1、AUC 并列给出。

### 5.5 读出层修正：极值压缩的诊断与处置

**诊断**（两层落盘证据）：演示场景中真实窟内 RH 在 72 h 内升至 **89.0%**，
而状态式线性读出只给 **34.6%**（`demo_forecast.csv`，RH_true 89.016 / RH_pred_lin 34.62，复现比 0.389）；
换成风险对齐的分位数读出（τ=0.95）后同一窗口的 72 h 峰值提高到 **49.1%**（复现比 0.552，提升 28%，
`demo_forecast.csv` 的 `RH_pred` 列）；
整体上，测试段 438 个峰值窗口中状态式读出 h=72 只复现真值峰值的 **55.9%**，
喂入真实未来外场（完美气象预报上界）也只有 **55.0%**（`derisk03_peak.csv`）——
**瓶颈在读出层与 MSE 目标本身，62% 阈值在最需要的极值场景下够不到**。

**处置**：Koopman 特征保持不变，仅把读出层换成梯度提升树。

| 指标 | 线性岭回归 | GBDT 非线性 | 变化 |
|---|---|---|---|
| RMSE @24 h | 7.270 | **6.626** | −8.9% |
| **极值捕捉比 @24 h** | 0.592 | **0.683** | **+15.4%** |
| **AUC @75%（最危险档）@24 h** | 0.759 | **0.879** | **+12.0 pp** |
| AUC @75% @72 h | 0.718 | **0.771** | +5.3 pp |

**结论（如实陈述自身设计的取舍）**：闭式线性读出保住了可微性，代价是极值保真度。
最终采用**双轨读出**——GBDT 面向业务预报（精度、极值保真与排序能力最优，仍为纯 CPU），
线性算子的谱与特征族权重面向物理解释与可微梯度链路。⚠️ 需注明这不是全面占优：
62% 档 F1 由线性的 0.100 降到 GBDT 的 0.085，代价是报警更密、精度略降。

### 5.7 真实洞穴观测的外部效度验证（ICCP）

§5.2–§5.5 的标签来自物理代理，为回应"合成标签闭环"的质疑，本节改用**完全独立的真实观测数据**：
以色列洞穴气候计划（ICCP，Zenodo `10.5281/zenodo.17505739`，CC-BY-4.0）在 12 个岩溶洞穴部署
42 台记录仪（"12 洞 / 42 台"取自 Zenodo 记录页元数据，**仓内无法复算**；本作品实际使用其中
**9 个**具备受光区—深处配对的洞穴、**16,944** 个逐小时配对时次，这两个数字可在
`code/results/iccp_transfer.csv` 逐位复算），2019-09-19 → 2021-07-04 逐小时记录气温与相对湿度。

**任务构造**：每个洞窟取近洞口受光区（`Lighting_Zone = Light`）与深处无光区（`Dark`）的记录仪
配对，**用受光区逐时 RH 驱动、预测深处逐时 RH**。该任务与本作品"室外 → 窟内"的架构同构，
但**不含任何物理模型、不含任何合成标签**。

**结果（测试段 20%：12 洞中 9 洞具备受光区—深处配对条件，再剔除 target 近乎常数的 Te'omim，最终在 8 个有效洞上统计）**

| 模型 | R² 中位数 | R² > 0 的洞数 | RMSE 中位数（RH 百分点） |
|---|---|---|---|
| Persistence（把洞口 RH 直接当深处，oracle 上界） | **−2.28** | — | — |
| FirstOrderTransfer（初稿方案：查表传递函数） | −0.255 | 3/8 | 7.18 |
| **Operator-Full（本作品）** | **+0.641** | **5/8** | **3.56** |

**三个结论**：

1. **洞口与深处的湿度是强解耦的**：Persistence 的 R² 中位数为 **−2.28**，即"直接把洞口 RH
   当作深处 RH"比"永远预测均值"还差。这从真实观测上说明了为什么初稿的查表传递函数不够——
   传播过程本身携带不可忽略的动力学。
2. **算子优于一阶传递函数：7/8 洞**，RMSE 中位数减半（7.18 → 3.56 个百分点）。
3. **但并非普遍有效**：Sela'（−6.41）、Murabba'at 2（−0.70）、Har Sifsof（−0.65）三洞的算子
   R² 为负，**如实报告**。Har Sifsof 深处 RH 均值 94.2%，Te'omim 恒为 100%（目标近似常数，
   R² 无定义，已由 `target_sd` 守卫剔除）——这类近饱和洞窟本方法不适用。

**边界声明（必须与结论同时阅读）**：ICCP 洞穴岩性为石灰岩/白云岩，与本作品标定的莫高窟
砾岩—砂岩不同；洞窟尺度与气候带（地中海 vs 干旱大陆性）亦不同。因此本节**只支持"输运算子
架构优于一阶传递函数"这一相对比较**，不外推到绝对精度，也不声称可直接迁移到莫高窟。

**同一数据给出的传递结构（附加证据）**：受光区 → 深处，日周期振幅比中位数 **0.184**
（范围 0.017–0.488），年周期振幅比中位数 **0.366**；日周期相位滞后中位数 **1163 分钟**
（约 19.4 h，仅当两端振幅均显著时才报告）。这与本作品物理模型"振幅衰减 + 相位滞后"的机制
定性一致。

### 5.8 物理代理与文献实测的同窟同期对照

§5.6 与 §5.7 检验的是**算法架构**能否迁移；本节检验**物理代理本身**是否可信。

对照组是 Gong et al. 2025 给出的**第 71 窟实测**（2019–2021 逐时）——即本作品标定所用的洞窟。
做**同期**对照（2019-01-01 → 2021-12-31），并施加 **2 年自旋期**以消除岩体导热链的初值瞬态。

关键点：**温度统计量从未参与标定**（标定目标只有日较差比、年极差比与窟内 RH 年均），
因此温度场的吻合是一次**独立**检验。

| 项 | 模型 | 文献实测 | 差值 |
|---|---|---|---|
| 窟内年均气温 | **12.45 °C** | 12.0 °C | **+0.45 K** |
| 窟内气温最高 | 25.58 °C | 25.8 °C | −0.22 K |
| 窟内气温最低 | −1.35 °C | −6.7 °C | **+5.35 K** |
| 窟内 RH 年均 | 32.24% | 30.8% | +1.44 pp |
| 窟内 RH 最低 / 最高 | 8.59 / 82.50% | 8.7 / 80.0% | −0.11 / +2.50 pp |
| 窟外年均气温（驱动） | 10.32 °C | 11.7 °C | −1.38 K（**数据源差异**） |

**读法**：模型窟外气温比现场站低 1.38 K（NASA POWER 再分析 vs 现场气象站），
但窟内年均气温仍落在实测 **0.45 K** 以内、暖端极值 **0.22 K** 以内。
**唯一显著偏差是冷端极值低估 5.35 K**，与年极差比偏小（0.468 vs 0.559）**同源**，
指向"年阻尼过强"——根因是本模型仅计吸收短波、**未建模夜间长波辐射冷却**。
该偏差已列入 §6.2 局限表，**不作隐藏**。

**顺带更正一处口径错误（诚信记录）**：初稿曾写"窟内年均温比窟外 +1.9 K，文献 +0.75 K，
偏暖约 1.2 K"。该表述有两处问题——①"+0.75 K"取自**另一个洞窟**（第 87 窟），非同窟；
② 本项目窟外气温来自**再分析数据**、文献来自**现场气象站**，两侧基准不同（本身差 1.38 K），
相减后等于把**驱动数据偏差**记成了窟内物理偏差。正确读法是同窟同期比绝对量，
即上表的 **12.45 vs 12.0 °C**。

**同窟同期之外的旁证：两组独立的天然"门开/门关"对照。** 除第 71 窟 2020 年疫情闭窟外，
莫高窟还有第二组完全独立的对照：陈海玲等对第 25/26/29/35 窟的 2007–2009 年监测发现，
**2008 年 5 月关闭第 26 窟后其窟内 RH 日较差月均值明显下降，同时开放第 25 窟后其日较差显著上升**；
2007 年 5–10 月 RH 日较差月均值，开放窟为 9.2–14.2%（第 26 窟）与 11.8–15.6%（第 29 窟），
而低强度/关闭窟仅 4.1–6.8%（第 25 窟）与 2.1–3.9%（第 35 窟）——**开放窟日波动约为关闭窟的 2–4 倍**。
两组对照来自**不同洞窟、不同年代、不同测量团队**，却给出同一结论：
**通风换气是窟内湿度日波动的主控**。这正是本方案把换气量 Q 而非 ACH 作为可迁移设计变量的依据，
也解释了为什么物理模型必须同时保留"岩体导热"与"通风平流"两条通道。

**关于岩体有效厚度的独立支持**：林波等（2013）在第 108 窟的实测显示，温度波动随深度衰减、
**大于 4.7 m 基本平稳**；湿度约 2.5 m 达 100%、**4.7 m 稳定 100%、波动基本消失**。
本模型取 `pillar_depth_m = 5.0 m`，与上述 4.7 m 同量级——这是三条独立文献中唯一**直接给出
"波动消失深度"**的一条。该文**未给出滞后时间/相位差**，故本项目不据此约束相位（如实记录，不作推断）。

**一个明确的不完整项（已列入局限表）**：周启友等（2018）在**第 108 窟**的夏季实测发现，
窟内确实存在净水汽输入，**但水汽不是经窟门进入的**，源头在东侧上层。本模型的平流通道只建了窟门，
因此在裂隙发育的洞窟中该通道描述不完整。这一条**不构成对本模型的否定**——本模型的门通道是按
第 71 窟门开/门关对照标定的，两者描述的是不同洞窟的不同通道——但它确实界定了适用范围。

管理决策周期，而现有文献方法的有效预报时效不超过 24 h。

### 5.10 可推广性

系统的核心是一个"**外场驱动 → 窟内代理 → 风险对齐**"的通用范式，
不依赖莫高窟的特有参数。已通过跨窟留一验证（第 71 窟标定 → 第 87 窟检验，5/6 通过）
证明其传递结构的可迁移性。

此外，**换气量以体积流量 Q（m³/h）而非换气次数 ACH 表达**——后者强依赖洞窟体积
（实测 ACH 仅来自 70–82 m³ 的小窟，而莫高窟大窟可达 1300 m³ 量级），Q 才是可迁移量。
这是**架构层面**而非参数层面的可迁移性设计。

可推广至：其他石窟寺（云冈、龙门、大足）、博物馆展陈微环境、岩画与土遗址保护。

### 5.11 社会效益

我国石窟寺分布广、监测条件差异大。本方案仅需**公开气象数据 + 普通 CPU**，
即可为缺乏窟内监测设备的中小型石窟提供风险预警能力，降低文保信息化的门槛。

## 六、总结与展望

### 6.1 经验总结

1. **问题重构**：把"文保应用"重构为"AI 算法问题"——
   在目标不可观测、判据为阈值+持续时间的条件下如何训练预报模型。
2. **算法贡献**：
   - **延迟嵌入输运算子**：可微、闭式、可解释的物理代理，24 h 点预报 R² **0.611**、AUC **0.860**
   - **物理动机特征设计**：逐配置独立调 β 后，完整配置（快变+慢变+Magnus）三指标同时最优
   - **风险对齐训练**：把预报目标从"平均误差最小"改为"阈值风险最小"
   - **读出层极值修正**：极值捕捉比 **0.592 → 0.683**，最危险档 AUC **0.759 → 0.879**
3. **实证厘清了初稿方案的失效机制**：文献标定一阶传递函数的**递归实现**因极点 a = 1.000920 > 1 必然饱和，
   AUC 0.4995、检出率 **0%**；但其**原文无自回归形式** AUC 达 **0.896**、排序能力反而更高，
   真正的短板是**绝对量级被压缩**——结论是「抓到了形状、丢掉了量级」，而不是「与随机无异」。
4. **外部效度**：跨窟留一验证 5/6 通过；并在 **ICCP 12 个真实岩溶洞穴**的独立观测上，
   输运算子的 R² 中位数 **+0.641** vs 一阶传递函数 **−0.255**（7/8 洞占优，RMSE 减半）。

### 6.2 局限的诚实声明

| 局限 | 说明 |
|---|---|
| **窟内无公开实测数据** | 窟内序列为**文献参数化物理模型生成的合成标签**，非实测。这是本方案最大的攻击面。缓解：§5.6 跨窟留一验证 + §5.7 真实洞穴（ICCP）独立验证，二者都只支持**相对比较**，不支撑绝对精度 |
| 真实洞穴验证存在 3 个失败案例 | ICCP 中 Sela'、Murabba'at 2、Har Sifsof 三洞算子 R² 为负；近饱和洞窟（RH 恒 100%）不适用，已由守卫剔除 |
| 极值捕捉比仅 0.60~0.68 | 无人能真正抓住极端事件 |
| 绝对阈值决策偏乐观 | 62% 绝对阈值判级在当前精度下偏乐观，建议配合概率输出使用 |
| 物理模型偏差 | **年阻尼偏强**——窟内气温冷端极值低估 **5.35 K**（模型 −1.35 °C vs 实测 −6.7 °C）。与之相对，**窟内年均气温差仅 0.45 K**（12.45 vs 12.0 °C）且温度统计量未参与标定。根因是未建模夜间长波辐射冷却 |
| 洞窟几何 | 模型代表中等规模旅游洞窟（约 67 m³），**不得外推到大窟** |
| 水汽通道假设不完整 | 本模型的平流通道只建了**窟门**。但周启友等（2018）在第 108 窟实测发现窟内净水汽输入**并非经窟门进入**（源头在东侧上层）。对裂隙发育的洞窟，本模型低估了非门通道。缓解：门通道参数是按第 71 窟门开/门关对照标定的，在该窟上成立；跨窟泛化能力由 §5.6（留一窟 5/6）与 §5.7（ICCP 7/8 洞占优）两条外部链路检验 |

### 6.3 未来规划

1. **文献图版数字化**：用 WebPlotDigitizer 数字化已发表曲线做留一窟交叉验证。
2. **接入深度时序骨干**（LSTM / PatchTST / iTransformer）与算子并联，
   检验"物理代理 + 深度骨干"的复合增益。
3. **概率化决策**：由分位数输出直接给出"超阈概率"，替代绝对阈值判级。
4. **真实窟内实测接入**：与文保单位合作部署窟内记录仪，把 ICCP 式的验证
   真正做在莫高窟上，检验不可迁移的绝对精度。

**关键算法代码**：算子读出的岭回归闭式解。两处细节是踩过坑才定下来的——**必须带截距项**（否则无法表达 RH 的 23% 均值，R² 掉到 −3.5），且**惩罚项只作用在斜率上、不能惩罚截距**（否则 β=1 时把均值压掉、偏差 −18 个百分点）。这两条结论的出处是源码注释 `code/src/operator/transport.py:320-326`（开发期诊断记录，**不在 `code/results/` 落盘**，此处按原始诊断数值引用）：

```
G = ZᵀZ / n + β · diag(mask)     # mask 在截距列上为 0
# 特征共线时改用增广最小二乘，避免条件数爆炸（曾出现 R² ≈ -1e30）
A = vstack([Z / sqrt(n), diag(sqrt(β) · mask)])
w = np.linalg.lstsq(A, b, rcond=None)[0]
ĥ_t = wᵀ · Ψ(u_t)
```

### 附录 5 被实验否定的设计（主动呈现）

本项目的结论是**实验驱动**而非论证驱动的。以下三个设计按**预登记判据**被实测否决，
保留记录：

| 被否定项 | 判据 | 实测结果 |
|---|---|---|
| Koopman :math:`K^h` 多步 rollout | 闭式 rollout 应优于直接读出 | h = 6/12/24/48/72 全时效劣于直接读出：R² **+0.505/+0.423/+0.311/+0.183/+0.117** vs **+0.668/+0.603/+0.545/+0.475/+0.429**（谱半径 max\|λ\| = 0.988088 < 1，故**不是数值发散，而是坐标张成不足**）。**原因**：多尺度滑动均值是外生汇总量，非不变 Koopman 可观测量 |
| twCRPS **内生权重**（创新点 1 的强化版） | 只有 C 显著优于 B 才证明贡献来自"内生权重" | C 优于 B 仅 **1/18**（验证段 1/9、测试段 0/9，`code/results/exp03_verdict.csv`）。**处置**：降级为"风险对齐训练" |
| **点预报直接判超阈**（"预测值 ≥ 阈值即报警"） | 点预报应能在阈值处给出可用的检出率 | 实测 MSE 点预报 `pt_R2` = **0.5854**、RMSE 7.109，但超阈**召回率仅 0.0465**（漏报 95.4%）、F1 **0.0724**（`code/results/exp03_abc_ablation.csv` test / 24 h / 62% 的 A 口径行）。**原因**：均方误差最优解系统性回归到均值，预报最大值结构性够不到阈值。**处置**：改为直接对风险评分规则做风险对齐训练（创新点 1） |

### 附录 6 数据真实性声明

- 本作品的**窟内温湿度序列为基于文献参数化物理模型生成的合成标签
  （physics-derived synthetic labels），不是实测数据**。
  原因是莫高窟及中国石窟的窟内温湿度**无公开实测数据集**。
- 外场驱动数据为 **NASA POWER 再分析资料**（MERRA-2 及偏差订正），
  **不是站点观测**。敦煌国家气象站（ISD 52418）**2023-04-28 之后停止上报**。
- 合成标签闭环**仅用于算法开发**；泛化性由跨窟留一验证（§5.6，5/6 通过）
  与待完成的 ICCP 真实洞穴数据验证两条独立链路检验。
- 所有物理参数均标注文献出处与 DOI（见 `docs/06_佐证材料.md` 第三节参数出处表与本文附录 3）。
